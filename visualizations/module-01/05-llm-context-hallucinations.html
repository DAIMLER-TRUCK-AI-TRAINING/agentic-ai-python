Topic 5

A next-token sampler with a fixed-size memory

An LLM picks each token by sampling from a probability distribution, and it sees only what fits in its context window on this call. Drag temperature and top-p to reshape the distribution. Then switch to Context window, push the conversation past 6 turns with Trim oldest, and watch the assistant confidently invent an asset ID.

Engineering takeaway: the model is stateless. Every call resends what it needs, and the context window is one budget shared by the system prompt, retrieved documents, history and the answer. Decide explicitly what to keep (state, summaries, retrieval) rather than letting truncation decide for you (Module 2 memory; Module 4 context engineering).
Common trap: “temperature 0 makes it deterministic.” Greedy decoding removes sampling, but serving infrastructure can still vary outputs between calls, and current Claude models do not expose the knob at all. Test structure (the schema validates, the cited ID exists), never exact wording.
