The model is one box; the blueprint is everything around it

The Enterprise Operations Assistant (incident triage → knowledge lookup → structured escalation) is a service with a model inside, not a model with some code attached. Unbounded historyLong incident threads get slower and dearer every turnSummarisation middleware plus explicit state for key facts (Topic 7)

Shared downstream rate limit429s from the status API at the 09:00 peakCache reads, back off, queue; agree a quota with the system owner
Single model routeProvider 429s or outages stop triage entirelySDK retries, a fallback model behind LLM_PROVIDER, batch for non-urgent work
Engineering takeaway: most of the bill, the latency and the incidents come from the boxes around the model: what tools return, what memory resends, how calls are sequenced. Review those boxes with the same rigour as any distributed system, and give every boundary a contract you can test.
Common trap: “the model has a 1M-token context window, so budgeting does not matter.” Every token is paid for on every call, long prompts are slower, and facts buried in the middle are recalled less reliably (Module 1, Topic 5). Set your own per-request budget and treat the model’s maximum as a hard limit, not a target.
