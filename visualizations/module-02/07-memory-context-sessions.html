Topic 7

Memory is whatever your application chooses to resend

The model is stateless: every turn, your code decides what it sees again. Play the Lab 04 support conversation (a VPN error after a password change, with off-topic detours) under buffer, window and summary memory, and watch the token line and the four facts its last two turns probe. Then keep key facts in explicit state, switch to a second user’s thread, and set every user’s thread_id to "default".

Outline memory types, current implementation

Outline termLangChain 1.x / LangGraphGrowsLosesUse when
Conversation bufferA checkpointer thread: create_agent(…, checkpointer=InMemorySaver()), invoked with {"configurable": {"thread_id": …}}Every turn, linearlyNothing, until the context window overflowsShort sessions
Window memorytrim_messages(messages, strategy="last", max_tokens=…, token_counter=…, start_on="human") before each model callBoundedEarly facts: the asset ID from turn 1Chat where only recent turns matter
Summary memorySummarizationMiddleware(model=…, trigger=("tokens", 1000), keep=("messages", 4))Slowly, plus summarisation callsBackground facts (team Finance, region EU) once off-topic turns pile upLong support sessions
Explicit stateTyped fields in the agent’s state or your database, rendered into every promptConstantOnly what you chose not to storeFacts the workflow depends on: IDs, team, region, decisions
 
from langchain.agents import create_agent
from langchain.agents.middleware import SummarizationMiddleware
from langgraph.checkpoint.memory import InMemorySaver      # development only; Module 4 uses a durable store

agent = create_agent(
    get_chat_model(), tools=tools,
    checkpointer=InMemorySaver(),                             # buffer: the thread's full history
    middleware=[SummarizationMiddleware(                      # summary: compress older turns
        model=get_chat_model(small=True), trigger=("tokens", 1000), keep=("messages", 4))],
)
config = {"configurable": {"thread_id": f"{conversation_id}:{user_id}"}}   # server-side, per user and per conversation
agent.invoke({"messages": [{"role": "user", "content": text}]}, config)
Outline vs current API: the outline’s “conversation buffer, summary memory, window memory” are the legacy ConversationBufferMemory, ConversationSummaryMemory and ConversationBufferWindowMemory classes, now in langchain-classic. Current LangChain keeps history in a LangGraph checkpointer thread and shapes what the model sees with message trimming and summarisation middleware. The trade-offs on this page are the same either way.
Common trap: treating thread_id as a cosmetic label. It is the key to a user’s stored conversation. Build it on the server from the authenticated user and the conversation, never from a request field alone, and never as a constant. Otherwise one user’s laptop ID turns up in another user’s answer.
