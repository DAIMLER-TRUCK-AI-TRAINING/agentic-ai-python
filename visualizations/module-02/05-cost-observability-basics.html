Topic 5

Every cost lever and every failure shows up in the trace

You cannot optimise what you do not measure. One assistant request is a tree of spans: two model calls, two tools and a validator, each with tokens, latency and a request ID. Pull the cost levers and watch the monthly bill and the eval score, then press Send request ▶ with a 429, a tool timeout or invalid JSON injected, and read how the trace and the structured logs tell the story.

Engineering takeaway: log one structured line per span with the trace ID, the provider request ID (resp._request_id / msg._request_id), the model, token usage including cached tokens, latency and the outcome. With LangChain, LANGSMITH_TRACING=true records this tree for you; for raw SDK calls, use langsmith.traceable or wrap_openai / wrap_anthropic. Module 5 adds Langfuse and dashboards.
Common trap: a value that changes on every request, such as a timestamp, a request UUID or unsorted JSON, near the top of the prompt. Caching silently stops working and every request pays the cache-write premium; turn on the bug to see the bill rise above the uncached baseline. Put static content first and check the cached-token fields in your logs.
