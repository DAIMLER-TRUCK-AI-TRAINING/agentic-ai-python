One tool-calling round trip, two wire formats

Tool calling is an RPC contract: the model asks for a call, your code runs it, and you send the result back. The OpenAI Responses API and the Claude Messages API agree on that loop but disagree on almost every field name. Step through the Lab 02 request “Is the EU VPN gateway healthy, and which KB article applies?”, flip the provider at any step to compare payloads, then make search_kb time out and watch how each API carries the error.

Outline vs current API: the outline says “OpenAI SDK … function calling”. This course uses the
    Responses API as the primary path. Much existing code still uses Chat Completions, where tools are
    {"type": "function", "function": {…}}, calls arrive in message.tool_calls, and results go back as
    role: "tool" messages. The loop is identical; only the field names change.

  
Common trap: passing model-chosen arguments straight to a system of record. A strict schema
    guarantees the shape of {"service": …}, not that this user may query that system. Validate, authorise and
    log every call in your own code, the same way you would for any untrusted RPC input (Module 5, tool gating).
