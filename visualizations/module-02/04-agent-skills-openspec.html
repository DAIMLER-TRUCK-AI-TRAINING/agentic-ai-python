Topic 4

Package what you repeat; specify what you build

A Skill turns a prompt you keep pasting into a folder the agent loads only when it needs it. A spec turns an agent idea into contracts a team can review. In Skill builder, move each part of a 2,600-token triage prompt to the right place and fix the name and description until all three test conversations behave. In OpenSpec builder, complete the half-written spec until the review finds no gaps.

Outline vs current API: “Agent Skills” are Anthropic Agent Skills: a folder whose SKILL.md
    starts with YAML frontmatter (name: at most 64 characters, lowercase letters, numbers and hyphens, no “anthropic” or
    “claude”; description: at most 1,024 characters, saying what it does and when to use it). Claude Code loads
    them from .claude/skills/; this repository’s generate-guide and generate-visualization skills are
    live examples. On the Claude API, Skills run in the code execution tool’s container. Treat a third-party Skill like installing
    software: audit its scripts before you enable it.


  
The OpenSpec walkthrough, stage by stage

  

    

      
StageWhat you writeAnti-pattern it prevents

Escalation rulesObservable triggers that hand over to a person“Escalate when unsure”, which never fires

      
    

  

  
Common trap: writing the spec after the code. In this course, OpenSpec is the agent-design template
    you complete before building (the name is also used by an open-source spec-driven development tool for AI coding
    assistants, built on the same spec-first idea). Contracts and boundaries agreed up front become the tests and tool gates of
    Modules 4 and 5.
