Topic 9

Let the agent decide when, where and how often to search

A classic RAG chain retrieves from one index for every message, whether or not it helps. Agentic RAG wraps each retriever as a tool, so the model chooses: no search for “thanks”, one search for a how-to, several hops across indexes for a question that joins an incident to a contract, and a logged knowledge gap when nothing fits. Run each question through both architectures and compare the calls, the cost and the answer.


    

  


  
Chain or agent?

  

    

      
AspectAlways-retrieve chainAgent with retriever tools

      
        
When it searchesEvery message, one fixed indexWhen the model decides a search will help, in whichever index fits

        
Multi-hop questionsCannot: one query, one index, one passChains calls: look up the incident, then search the contracts with what it learnt

        
Query qualityThe user’s words, as typedThe model rewrites the query for each index (IDs, keywords, synonyms)

        
Cost and latencyPredictable: one retrieval, one model callVariable: one to several model calls; cap them

        
Failure modesIrrelevant context forced into every promptSkipping a search it needed; looping; choosing the wrong tool

        
Knowledge managementSilent when nothing fitsCan call a tool to record the gap for the KB owners

      
    

  

  
Engineering takeaway: wrap each index as its own tool with a precise description of what it contains,
    return chunk IDs and scores so the model (and your logs) can judge relevance, cap model and tool calls per request, and test tool
    choice with labelled questions, as you test retrieval. Module 4 turns this loop into an explicit LangGraph workflow.

  
Common trap: assuming the agent will always search. Models answer from their own knowledge when a
    question looks easy. Say in the system prompt that internal facts must come from a tool, check in your evals that the right tool was
    called, and refuse to accept an answer with no citations for a question that needs one.
