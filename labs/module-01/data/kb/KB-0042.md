# KB-0042 — VPN client rejects credentials after a password change

| Field | Value |
| ----- | ----- |
| Article ID | KB-0042 |
| Owner | Network Ops |
| Applies to | Remote-access VPN client, all managed laptops (EU, US, APAC) |
| Last reviewed | 2026-08-30 |
| Classification | Internal |

## Symptoms

After changing their directory password, a user starts the VPN client and sees
"Authentication failed: invalid credentials", even though the new password
works for webmail and the intranet.

## Cause

The VPN client stores the previous password in its saved-credential cache and
keeps offering it. A second, less common cause is directory replication: the
VPN gateways in some regions can take up to 15 minutes to receive a password
change.

## Resolution

1. Wait 15 minutes after the password change so that every VPN gateway has the new password.
2. Quit the VPN client completely from the system tray or menu bar; closing the window is not enough.
3. Open the client's settings, select "Saved credentials" and remove the entry for the corporate gateway.
4. Start the client again, sign in with the new password and approve the MFA push on your phone.
5. If the connection still fails after 30 minutes, raise an incident in the "Network Access" category at priority P3 and attach the client's log bundle (Help → Export logs).

## Escalation

L1 analysts escalate to the Network Ops L2 queue when step 5 applies or when more
than five users at the same site report the problem within an hour, which
points to a gateway fault rather than a client cache.
