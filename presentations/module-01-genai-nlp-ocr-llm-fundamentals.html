Topic 1 · GenAI landscape & foundation models

Production systems mix layers: use the cheapest one that meets a measured requirement

Rule-based

Nothing is learned. A regex routes tickets that mention VPN to Network Ops.

Classical ML

A function over features you engineer: a TF-IDF ticket-priority classifier.

Deep learning

The network learns features and function: a BERT encoder tags people and places.

Generative AI

A distribution sampled token by token: it drafts the INC-104233 escalation.

This is survey level, so move quickly: the taxonomy is not the point. The point is the production mix on the right. The regex finds the incident ID for free and deterministically, a 110-million-parameter encoder tags names on a CPU, and the decoder LLM runs only where generation is genuinely needed. Topic 1 · GenAI landscape & foundation models

A foundation model is frozen general knowledge: you adapt it at request time

Enterprise reality: the same model reaches you through several doors. Claude Opus 5.5 is claude-opus-5-5 on the Claude API and anthropic.claude-opus-5-5 on Amazon Bedrock. The ID, regions, features, price and retirement date can differ per platform, so check that platform's own model page before you commit.
The provider trains the model once, on web-scale text by next-token prediction, then post-trains it to follow instructions, then freezes the weights. It knows nothing after its cutoff (June 2026 for the current Claude models) and nothing private, so anything newer or internal must arrive in the request: that is why Modules 2 to 4 are about prompts, retrieval and tools far more than fine-tuning. You also choose a door: the provider API gets the newest models first; a hyperscaler brings existing contracts, private networking and regional processing; open weights keep data in your estate at a fixed infrastructure cost; specialist services such as OCR come with task-specific accuracy. Ask: which door does your procurement already open, and does it limit which models you can use?

Topic 3 · OCR for enterprise documents Cloud OCR: instructor demo, no separate lab

Measure OCR before you fix it: layout and image quality need different cures

Layout error → page segmentation

The default psm 3 emits table columns as separate blocks; psm 4 keeps each row together. Clean invoice: 0.403 → 0.004.

Image error → preprocessing

Grey, contrast, median filter, deskew, Otsu threshold: the scan falls from 0.492 to 0.029. Page segmentation alone barely helps.

Never preprocess blindly

The clean invoice gets worse (0.004 → 0.011), and the deskew cannot correct the photo's perspective (0.129).

Confidence is OCR's gift

Per-word confidence is a signal an LLM does not give you. Gate the ID, total, date and IBAN on it, never the page average.

The chart is deterministic for Tesseract 5.5.3, and learners reproduce it in Lab 02 Parts 1 and 2; other versions give different third decimals but the same relationships. The clean invoice's 40% character error rate is a reading-order problem, not a recognition problem, so page segmentation fixes it. The scan's error is image quality, so preprocessing fixes it, and the same preprocessing makes the clean image slightly worse: measure, never preprocess blindly. The field gate on the right is the guide's representative output for the degraded scan: the true total is 1,491.24 and the true due date is 21 Oct 2026, so both misreads go to a human. Ask: what is your business-critical field set, and what threshold would you defend to Finance?
Topic 4 · Transformer architecture & attention

Self-attention lets each token read the others: that mechanism explains the bill

FamilyAttentionTrained toExamplesWhere you use it
Encoder-onlyBidirectionalFill in masked tokensBERT, mDeBERTa, Sentence-BERT encodersNER, POS, zero-shot NLI, embeddings
Decoder-onlyCausal, left to rightPredict the next tokenGPT and Claude families, gpt-oss, SmolLM2Generation, reasoning and tool use (Modules 2–5)
Encoder–decoderEncoder, plus cross-attentionMap one sequence to anotherThe original Transformer, T5, TrOCRTranslation, summarisation, transformer OCR
You will not implement a transformer; you need just enough to explain three production facts. Self-attention lets every token draw information from every other token, so compute grows roughly with the square of the sequence length and long prompts add latency. The prompt is processed in one parallel pass, but output comes one token per step through the KV cache, which is one reason output tokens cost five times input on Claude Opus 5.5. The matrix is exact for the guide's seeded four-token toy; watch each row light up in turn, and note the causal mask. Ask: which family would you deploy for NER on 6,000 tickets a day, and why not the biggest decoder you can buy?

Consistency comes fromA constrained task, a schema, validation, and tests that assert on structure rather than on exact text
A model never writes an answer: it scores every vocabulary token, turns the scores into probabilities and picks one, over and over. Temperature divides the logits before the softmax; the four charts are exact maths for one ticket's priority (logits 3.1, 2.6, 1.4 and −0.5). At T = 1.0 the ticket comes back P1 about a third of the time, and that variability comes from decoding, before any question of prompt quality. Then the API reality, verified for the course pins: OpenAI accepts temperature only at reasoning effort none, on the models that offer it; the Claude SDK has no sampling arguments, and current Claude models accept only the defaults. Lab 01 Part 2 sweeps temperature on a local SmolLM2 model and provokes both errors on purpose. Ask: if you cannot turn the temperature down, how do you get consistent triage?
Topic 5 · LLM architecture: context windows, hallucinations & limits

The context window is working memory, not storage

# OpenAI Responses API · count, cap, check n = openai_client.responses.input_tokens.count( model=OPENAI_MODEL, input=log).input_tokens r = openai_client.responses.create(model=OPENAI_MODEL, input=log, max_output_tokens=64) if r.status == "incomplete": r.incomplete_details.reason # "max_output_tokens"
# Claude Messages API · count, cap, check n = claude_client.messages.count_tokens( model=ANTHROPIC_MODEL, messages=msgs).input_tokens m = claude_client.messages.create(model=ANTHROPIC_MODEL, max_tokens=64, messages=msgs) m.stop_reason # "end_turn" · "max_tokens" · "refusal" # · "model_context_window_exceeded"
The window is the model's working memory for one request: instructions, tool definitions, history, retrieved documents, OCR text, the current message and the output, thinking included, all count. Every current model in both families offers about a million tokens, so the problem has moved from fitting text in to choosing what goes in. You pay for every token on every call, latency rises, and facts in the middle are used less well; the curve is illustrative of the lost-in-the-middle result and Anthropic's "context rot". Count with each provider's own endpoint, because tokenisers differ and Japanese costs 1.56 times English for the same complaint; reserve the output; read the stop condition before you trust the text. Lab 01 Part 4 ends with a pre-flight guard that refuses an oversized request before it costs anything. Ask: what is your rule when a request would not fit: trim, summarise or retrieve?
Topic 5 · LLM architecture: context windows, hallucinations & limits

Hallucination is expected behaviour: ground it, permit abstention, verify in code

# Lab 01 Part 3 · one Pydantic schema drives structured output on both providers class GroundedAnswer(BaseModel): supported: bool # True only if the article states the answer answer: str | None # null when the article does not contain it quote: str | None # one sentence copied verbatim from the article a = openai_client.responses.parse(..., text_format=GroundedAnswer).output_parsed a = claude_client.messages.parse(..., output_format=GroundedAnswer).parsed_output verified = a.quote is not None and a.quote in kb_0042_text # code decides, not the model
A hallucination is fluent output unsupported by the world (factuality) or by the supplied context (faithfulness). Training and evaluation reward a confident guess over "I don't know", so treat it as expected behaviour and engineer around it rather than prompting it away. The first five triggers are the probes learners run in Lab 01 Part 3; the forced-format one returns in Lab 02, where a required po_number gets invented. Grounding means three things at once: supply the source, permit abstention, and demand evidence your code can check deterministically. If a row comes back UNVERIFIED, the model invented its own evidence: that is a finding, not a broken lab. Ask: which fields in your systems could you verify against a system of record before anyone acts on them?
Topic 6 · Embeddings & multilingual semantic similarity

Multilingual embeddings put a German ticket next to the English article that solves it

A score is not a probability

Rank within one query. Set thresholds from labelled pairs, per model and per language, because the scales differ.

Negation barely moves the vector

"The VPN works" versus "does not work" after the password change: 0.96–0.98. Use a classifier for polarity.

Identifiers are invisible

INC-104233 versus INC-104234: 0.97–0.99. Extract IDs with a pattern and look them up exactly.

Vectors belong to one model

Store model_id with every vector and never mix versions in an index: an upgrade is a data migration.

An embedding is a fixed-length feature vector for meaning; cosine similarity measures the angle between two of them. The multilingual Sentence Transformers model was trained by knowledge distillation, so a sentence and its translations land almost on top of each other; the English-only model only sees shared sub-words, which is why the Latin-script "VPN" keeps Hindi and Japanese above zero. On Lab 02's 28 tickets the English-only model's median best score is 0.11 against 0.70, so a 0.35 escalation rule would push most of the queue to humans. Anthropic offers no embedding model of its own (its docs point to Voyage AI); OpenAI has text-embedding-3; the labs use local models, which serve either provider. Ask: what happens to your vector index on the day you upgrade the embedding model?
Topic 7 · Model selection & Responsible AI

Pick the agent type first, then the cheapest tier that passes your evals

1 · Filter

Hard constraints such as EU residency or an existing data-processing agreement are filters, not weights.

2 · Shortlist

At least one OpenAI and one Claude model, plus a local baseline, that can all hold the worst-case input.

3 · Measure

At least 50 labelled items: quality, p95 latency and cost per completed task, not price per token.

4 · Decide and date it

Break ties with a criterion agreed before scoring, and record it in the comparison sheet with a review date.

Read the grid left to right as more autonomy, and top to bottom as cheaper tiers. The agent type comes first: if you can draw the flowchart, build a workflow and let code own the control flow. The costs are Lab 03's numbers at list prices on 27 October 2026, with caching and the Batch API where a scenario allows them: UC-1 on Claude Haiku 5.5 or GPT-6 Luna, UC-3 on GPT-6.1 Terra or Claude Sonnet 5.5, UC-4 on Sonnet 5.5 or GPT-6.1 Sol, UC-2 on Claude Opus 5.5. Within a provider the tiers span about a hundredfold; across providers the same tier often costs the same. Model IDs change several times a year, so course code reads them from OPENAI_MODEL and ANTHROPIC_MODEL, never from source. Ask: for UC-2, at 120 requests a day, is the bill or the evidence the deciding factor?

Responsible AI is real only as a test, a log field, a gate or an owner

FrameworkWhat it isWhy you will meet it

The outline gives Responsible AI thirty minutes and no separate exercise, because Module 5 engineers the controls; compress this slide if pacing slips. Map each principle onto the pipeline you are already building. Privacy is redaction before any external call, plus a processing region (Claude's inference_geo, or a cloud region). Transparency is disclosing AI use and logging the model ID, version and a reason. Safety is the validation gate and the human in the loop from the OCR slides. Accountability makes every model upgrade a CHG change request with an owner, a rollback and evals run first. Fairness is per-language evaluation, because tickets in some languages match less reliably and nobody notices without the slice. Lab 03's comparison sheet asks the bias, transparency and governance questions for your chosen model. Ask: who in your organisation owns the model choice, and what gets logged?

Wrap-up

Key takeaways, and a quick self-check

01Tokens are the unit of everything

Limits, latency and cost are counted in tokens, per tokeniser: Japanese costs 1.56× English. Count with the provider's endpoint.

02OCR is lossy ETL

Check for a text layer first, diagnose layout versus image quality, and gate business-critical fields on confidence.

03Working memory, not storage

A million tokens is capacity, not a strategy: you pay for every token, and facts in the middle get missed.

04Expect hallucination

Ground the model, permit abstention, and verify quotes, IDs and numbers in code. Assert on structure, not text.

05Embeddings are per-model coordinates

Thresholds per model and language, one model per index, and never match identifiers by embedding.

06The cheapest tier that passes

Agent type first, hard constraints as filters, cost per completed task, and a decision with a review date.
